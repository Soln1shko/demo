# Financial Intelligence: Business Twin + Credit Quest

Локальный демонстрационный модуль для двух задач: **Business Twin** показывает помесячное будущее бизнеса с кредитом и без него, **Credit Quest** ищет допустимые действия для улучшения предварительной оценки заявки. Все входные компании имеют синтетический ID `demo_*`. Модуль не вызывает LLM, платный API или банковские системы. Вероятность кассового разрыва считает отдельный существующий сервис `cash_cap`.

## Один сквозной сценарий

1. `POST /ml/forecast` принимает 6–36 последовательных месяцев денежных поступлений, операционных расходов, налогов, старых долговых платежей и остатка денег. Возвращает прогноз на 1–12 месяцев без нового кредита.
2. `POST /ml/simulate` принимает прогноз и необязательный `loan`. Считает базовую, оптимистичную и стрессовую траектории с аннуитетным платежом. Вызовите его дважды с тем же прогнозом: без `loan` и с `loan`, чтобы сравнить будущее бизнеса.
3. `POST /ml/quest/generate` принимает историю, поля действующего скоринга, тот же кредит, остаток старого долга, минимально полезную сумму и целевой условный балл. Возвращает до трёх планов. Если цель уже достигнута, список пуст.
4. `POST /ml/quest/recalculate` принимает те же входы и `actions` из выбранного плана. Проверяет, что действия допустимы для исходного снимка, и возвращает новый прогноз, денежные траектории и пересчитанный балл.

`GET /ml/demo/{stable|seasonal|risky}` создаёт готовые профили ИП и ООО в трёх отраслях с фиксированным seed. Полные JSON-схемы доступны в `/docs` и `/openapi.json`.

## Расчёт и допущения

| Часть | Вход | Результат и смысл |
| --- | --- | --- |
| Прогноз | Финансовая история | Ограниченный тренд, постоянная и переменная части расходов; при 18+ месяцах учитывается прошлый одноимённый месяц. Когда выручка равна нулю, постоянные расходы и налоги не исчезают. Диапазон эвристический, не калиброванный доверительный интервал. |
| Денежный двойник | Прогноз, ставка, срок, сумма, использование средств и явно заданный эффект | Выдача и инвестиция проходят отдельно; кредит сам по себе не становится выручкой. Эффект на выручку нарастает за `ramp_months`. Налоги и старые платежи учитываются отдельно. |
| Сценарии | Прогноз и параметры кредита | Три детерминированные траектории: базовая, оптимистичная и стрессовая. Отрицательный `minimum_cash` означает дефицит денег в конкретном сценарии, а не его вероятность. |
| Квест | Снимок заявки и доступные действия | Пересчёт через `ScoringEngine` с действующей версией весов. Балл равен `round((1 - risk_probability) * 100)`. Это условная визуализация риска, не вероятность одобрения. |

В квесте перебираются уменьшение суммы кредита при сохранении минимально полезной суммы, снижение ежемесячных расходов на 5–10% и погашение 25–50% существующего долга при сохранении резерва не меньше месячных расходов. План объединяет максимум два разных действия. Снижение расходов требует подтверждения новыми выписками: экономия в денежном прогнозе начинается после трёх месяцев. Погашение долга тратит деньги и снижает старый платёж; уменьшение инвестиций пропорционально снижает сценарный экономический эффект. Планы, которые ухудшают уже отрицательный минимальный остаток или делают положительный остаток отрицательным, не рекомендуются. Возраст бизнеса, кредитная история, просрочки и залог автоматически не «улучшаются».

Параметры модели собраны в типизированной `FinancialConfig` (`config.py`), а не разбросаны по API. Формулы находятся в `forecast.py`, `simulation.py` и `quest.py`.

## Поля и ограничения

- `ForecastRequest.history`: месяцы от старого к новому без пропусков, дата каждого месяца — первое число; `cash_balance` — остаток на конец соответствующего месяца. Денежные величины — целые рубли.
- `LoanScenario`: `amount`, `term_months`, `annual_rate_percent`, `purpose`, `investment_amount`, `monthly_revenue_effect`, `monthly_expense_effect`, `ramp_months`. Для рефинансирования обязательны `old_debt_payoff` и `old_payment_reduction`; сумма использования средств не может превысить выдачу.
- `QuestRequest.scoring` использует тот же контракт, что `/v1/scoring`. Его сумма, срок, выручка последнего месяца и возраст бизнеса должны совпадать с финансовым снимком. `existing_debt_balance` и `minimum_acceptable_amount` явно задаёт вызывающая сторона.
- Ошибки схемы и доменных ограничений возвращают HTTP `422`. Неизвестный демонстрационный профиль возвращает `422`. Расчёты не сохраняют заявки.

## Проверка

```bash
uv run pytest -q tests/test_financial_intelligence.py
uv run uvicorn app.main:app --app-dir src
```

Для ручной проверки возьмите JSON из `GET /ml/demo/risky`, передайте его `forecast_request` в `/ml/forecast`, вызовите `/ml/simulate` с `loan` и без него, затем `/ml/quest/generate` и `/ml/quest/recalculate`. Тест покрывает эту последовательность, график кредита, реакцию на ставку и отклонение подменённых действий. `rolling_backtest` позволяет оценивать однократный прогноз на последних месяцах; хорошая ошибка на синтетических демо не доказывает качество на реальных бизнесах.

## Ограничения

Это объяснимый baseline, без обученного CatBoost. Доля постоянных расходов в прототипе принята равной 50%; эффекты инвестиций задаёт вызывающая сторона. Нет реальной калибровки интервалов, фактической вероятности одобрения, инфляции, индивидуального налогового режима, комиссий и досрочных погашений нового кредита. Для реального кредитования потребуются исторические данные, временной backtest по отраслям, калибровка, мониторинг дрейфа, проверка данных и банковские правила решения. `DecisionService` здесь не вызывается: скоринговый балл не является решением. Результаты проверки на кейсах приведены в [отчёте](../../../docs/QUALITY_AUDIT.md).
