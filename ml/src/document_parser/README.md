# Парсер кредитных документов

`POST /v1/documents/parse` распознаёт загруженные файлы и предлагает заполнить универсальный профиль клиента. Клиент подтверждает **только `profile`**. `additional_facts` возвращаются отдельно и не входят в форму подтверждения.

## Загрузка

`multipart/form-data`: `case_id` вида `DEMO-*` и от 1 до 8 полей `files`. Допускаются PDF, PNG и JPEG до 10 000 000 байт каждый. Сервер сверяет сигнатуру файла с расширением; на документ допускается до 20 страниц, на весь OCR-текст — до 60 000 символов. Файлы обрабатываются во временном каталоге и удаляются после OCR.

```bash
curl -sS -X POST http://127.0.0.1:8000/v1/documents/parse \
  -F 'case_id=DEMO-001' -F 'files=@./demo-statement.pdf;type=application/pdf'
```

Используйте синтетический файл; `demo-statement.pdf` в репозитории не хранится.

## Что возвращается

| Часть ответа | Смысл |
| --- | --- |
| `profile` | Всегда одинаковая структура: форма бизнеса, налоговый режим, демонстрационные реквизиты, отрасль, возраст, месячные выручка и расходы, маржа, действующий долг и платёж. Неизвестные поля равны `null` |
| `field_evidence[]` | Для каждого заполненного поля: имя, `document_id`, номер страницы и цитата из OCR |
| `additional_facts[]` | Иные относящиеся к кредиту факты с источниками; остаются вне подтверждаемого профиля |
| `conflicts[]` | Противоречивые значения и ID документов; спорное поле следует оставить незаполненным |
| `missing_fields[]` | Имена полей профиля со значением `null` |
| `case_id`, `model`, `synthetic` | Демонстрационный ID, модель OpenRouter и признак синтетического результата |

Локальный PaddleOCR сначала распознаёт строки и таблицы лёгкой кириллической моделью; если текст не найден, запускает более тяжёлый PP-StructureV3. OpenRouter получает OCR-страницы с ID и извлекает JSON. Сервер требует `field_evidence` для каждого заполненного поля и проверяет, что цитата встречается на заявленной странице. Это проверка происхождения, а не подлинности документа или правильности интерпретации суммы.

## Типовые документы

Набор зависит от формы бизнеса, налогового режима и продукта. Для демонстрации подходят декларация или КУДиР ИП, баланс и отчёт о финансовых результатах ООО, выписки по счетам, сведения об обязательствах и документы о цели займа. Справка о доходах физлица может понадобиться для участника сделки, но не заменяет подтверждение выручки бизнеса. Список не является универсальным требованием банка; актуальные требования нужно проверять отдельно.

## Ошибки и проверка

Неверный файл, пустой OCR или превышение лимитов дают `422`. Ответ LLM вне схемы либо с цитатой, которой нет на указанной странице, даёт `502`. Без OpenRouter — `503`. При первом OCR-вызове PaddleOCR может загружать модели; для автономного запуска их нужно заранее сохранить в образе или локальном кэше. `uv run pytest -q tests/test_document_parser.py tests/test_api.py` проверяет схему и HTTP-путь с подменным OCR и LLM. Дополнительно синтетический PNG с кириллическими выручкой и расходами был разобран в запущенном контейнере с реальным PaddleOCR и LLM за 23,84 с после прогрева модели; это не измерение качества на произвольных банковских сканах.
