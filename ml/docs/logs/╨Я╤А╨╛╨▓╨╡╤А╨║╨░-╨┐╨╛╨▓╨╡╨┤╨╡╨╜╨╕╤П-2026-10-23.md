## LLM и OCR: граница проверки

Интеграционные тесты с детерминированной подменой LLM и OCR проверяют маршруты и контракт `underwriting`, `decision-explainer`, `crm-copilot`, `document-parser`, `assistant/answer`, `credit-advisor`: классификацию сложности и приоритета, ссылки на данные снимка, отсутствие объяснения отказа без риска, блокировку окончательного ответа CRM при нехватке данных, разделение профиля и `additional_facts`, проверку источников OCR и допустимых `knowledge_id`.

Живой OpenRouter сначала ответил на три запроса `credit-advisor`. Следующие запросы к `assistant/answer`, `underwriting/summary` и `crm-copilot/reply` получили `503`: провайдер вернул HTTP `429`. Сквозной живой ответ этих ручек и `decision-explainer/refusal` в этой проверке **не подтверждён**. Живой OCR документа также не проверен; тестовый OCR распознаёт заданный текст. Ошибку `429` приложение не маскирует готовым ответом.

До исправления поиск на запрос «Какие ограничения у кредита продавцу маркетплейса?» возвращал общие фрагменты о залоге; `assistant/answer` ответил `502`, потому что LLM не указала допустимый `knowledge_id`. После исправления поиска релевантные фрагменты находятся, но финальный ответ повторно не проверен из-за лимита провайдера.

## Исправления и оставшиеся ограничения

- `nba`: добавлена проверка применимости баннера до ранжирования; усилены веса явных признаков офлайн-точки, маркетплейса и ВЭД. Контрастные сценарии закреплены тестами.
- `ai_assistant`: лексический индекс сближает длинные русские словоформы по короткой основе; для кредита продавцам маркетплейсов добавлено поисковое название. Точный источник по конкретному продукту находится в топе.
- `cash-gap`: `cash_gap_probability` остаётся оценкой baseline-модели и сейчас не меняется с `forecast_days`; выбранный горизонт меняет `estimated_shortfall`. Это ограничение нужно учитывать в интерфейсе.
- `credit-advisor`: `preliminary_approval_probability = 1 - risk_probability` — модельная предварительная величина, не откалиброванная вероятность решения банка. LLM может менять порядок только среди локально допущенных продуктов.
- Наличие допустимой ссылки на источник в тексте LLM не доказывает фактическую верность каждого предложения. Для внешней отправки объяснений и CRM-черновиков нужна проверка сотрудника.
