# АльфаХак: умный кредитный кабинет

## Контекст

Это прототип цифрового кредитного конвейера для малого и микробизнеса. Он связывает путь предпринимателя и внутреннюю обработку заявки банком. Все данные демонстрационные и синтетические: реальные персональные, банковские и кредитные данные в репозиторий не попадают.

## Режим работы

- Язык ответов, документации и пользовательских текстов - русский. Код, API-поля и имена сущностей - английский.
- Сначала делаем один сервис или вертикальный срез, затем проверяем его сквозным сценарием. Не реализуем все экраны одновременно.
- Скоринг, решение и интерфейс не подменяют друг друга. ScoringService возвращает оценку риска и факторы, DecisionService применяет продуктовые правила и возвращает решение с причинами.
- Внешние ФНС, БКИ и банковские системы заменяем локальными детерминированными симуляторами. Это явно указывается в документации и THIRD_PARTY_NOTICES.
- Любое решение должно быть воспроизводимо локально через Docker Compose и не зависеть от платных API, закрытых систем или облака.

## Данные и ML

- Любые наборы для разработки, тестов и демо генерируются кодом с seed и схемой данных. Не коммитим сгенерированные CSV, SQLite-файлы, артефакты обучения, логи и персональные данные.
- Генератор обязан создавать достаточный объём и разнообразие: ИП и ООО, разные отрасли, возраст бизнеса, финансовые профили, долговую нагрузку, кредитную историю и пограничные кейсы для правил.
- Синтетика не должна содержать реальные ИНН, ФИО, адреса, телефоны или реквизиты. Для идентификаторов использовать заведомо демонстрационные значения.
- Каждая модель или правило документирует входные поля, целевой результат, допущения, ограничения и способ проверки. Сначала объяснимый baseline, затем ML только при измеримой пользе.
- Фиксируем random seed в тестах и демо. Проверяем инварианты генератора и распределения, а не только факт создания файла.

## Архитектура

```text
src/credit_cabinet/      прикладной код
tests/                   unit, integration и e2e-тесты
scripts/                 генерация синтетики и служебные команды
docs/business/           границы MVP, сценарии и допущения
docs/architecture/       API, модель данных, состояния, схема
docs/logs/               изменения и эксперименты
```

Новый код располагается в src-layout. Бизнес-пороги, веса, лимиты и seed не хардкодятся в сервисах: для них используются типизированные конфигурации. Один модуль отвечает за одну предметную роль.

## Качество

- Python 3.13, зависимости запускаются через `uv`.
- Перед передачей изменений выполнить: `uv run ruff format --check .`, `uv run ruff check .`, `uv run mypy src`, `uv run pytest -q`, `git diff --check`.
- После появления HTTP API добавить интеграционный тест основного сценария и проверить Swagger/OpenAPI.
- После появления Docker проверить чистый запуск `docker compose up --build` и пройти README-сценарий в браузере.

## Безопасность

- Не коммитить `.env`, ключи, токены, реальные данные или локальные базы. Публичны только `.env.example` и синтетические генераторы.
- Не выдавать демонстрационный скоринг за реальное банковское решение и не использовать его для настоящего кредитования.
